topics/<topic>.md holds a THEME that spans TWO OR MORE people -- either several people involved at once, or a pattern that recurs over time across conversations and people (e.g. shared school stress, a recurring vacation wish). A topic is NEVER about one single person: a theme that only ever concerns one person belongs in that person's profile, even when it recurs, and never in a topic file. When today's journals show such a cross-person pattern, consolidate it into a topic file instead of only general/family.md.
Every topic file must START with an "Aliases:" line ("Aliases: also known as <other names>"), which serves as a matching anchor against duplicates. Content: the theme, what is known about it, with cross-references to the involved people.
general/topic-index.md is the topic registry: for EVERY topic file you create or change, also stage general/topic-index.md with one line per topic -- topic path, a one-line semantic description (not just a slug), and the involved people.
When you create a topic file, MOVE the theme out of the individual profiles: for every involved person whose people/<name>.md mentions the theme (e.g. in Open Topics or Ideas, Interests & Goals), stage an updated version of that profile with the theme REMOVED, leaving at most a one-line pointer to the topic file -- never keep the full theme in BOTH the person's profile and the topic file.
DUPLICATE PREVENTION, first line of defense: before creating a new topic file, check the EXISTING topics/*.md files -- even if the name sounds different. Read a candidate file's content (and its Aliases line) with get_long_term_file; if an existing topic fits the theme content-wise, extend THAT file instead of creating a new one. Match semantically, not only by name.
